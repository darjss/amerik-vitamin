# Archaeology: where the LEGACY.md bugs came from

Where each of the 12 "bugs never to repeat" in [../LEGACY.md](../LEGACY.md) was born. Also why ADR 0012 has a 12-hour handoff timer, when each cache layer appeared, and the nastiest bugs fixed with models in 2026. Sources are vit-store `origin/main` git history, `gh` PR data, and agent transcripts from codex, opencode, pi, bpi, devin, cursor and the Claude Code prompt history.

## Headlines

- **7 of the 12 bugs were born on day one.** They came in the first two vit-store commits on 2025-07-07, `18b3225` "first commit" and `0753bf7` "trpc routers done?". That was before any surviving session log, when the code came from Cursor agents, ChatGPT and DeepSeek copy-paste, and hand edits. They are bugs 1, 2, 3, 5, 8, 10 and the `out_of_stock` part of 12. Every later rewrite carried them forward.
- **Bug 9 (a new Postgres pool per `db()`) came from a direct ask** to opencode claude-opus-4.5 on 2026-01-21: "isnt there a simple way to access cf bindings without accessing the context object".
- **Nobody decided on the 12-hour timer.** It came in with a Codex review fix, and no reason is given anywhere. The explicit resume button arrived in the same fix. Keep the button and drop the expiry, and it matches MANIFESTO.
- **Cache layers only ever got added.** The KV tRPC cache from 2025-10-13 is still on main, under the Workers Cache, the Astro edge HTML cache and Upstash.

**Caveats**

- Several fixes were split across many commits, so session counts are approximate.
- Claude Code sessions have no model recorded. The models I name for them are inferred.
- Pre-2026 sessions were lost, so those rows are git only.
- LEGACY.md line numbers do not all match origin/main. For example, `routers/admin/product.ts` now stores `oldSlugs` on update, but the name rebuild at line 493 is still there.

## (b) ADR 0012 and the 12-hour timer

The timer is in `plans/029-messenger-bot-rewrite.md` as commit `0deae1d` (2026-10-01 12:58 UTC). The original plan, `37236b5`, said only that the bot "pauses for the thread" and listed `paused_until` in the meta table. No duration was set.

`0deae1d` is titled "address Codex review". The plan's review log says "Reviewed by Codex GPT-6 Astra (high reasoning)… All 16 findings accepted." Finding 12 is "Pause not enforced in code", and its fix is "`paused_until` gate in `process`, Telegram resume button, admin route". The plan text then reads:

> `handoff({ reason })` sets `paused_until = now + 12 h`… Resume: an inline "▶ Бот үргэлжлүүлэх" button on the Telegram alert, plus `POST /admin/conversations/:id/resume`. Both clear `paused_until`.

- **The only data in the plan:** human admin reply time is "median 2.6 min, p90 55 min".
- **What I could not find:** no sentence anywhere says why 12 hours. PR #342 says "pauses the thread 12 h". The ADR just repeats it.
- **No transcript:** I found no Oct-1 session transcript for the plan author. The coordinator can treat "12 h" as an unexplained default from the Codex-review fix.
- **Not a pure timer:** explicit resume (Telegram button and admin route) exists too. The timer is an expiry on top. That still conflicts with the manifesto's "tap only" rule.
